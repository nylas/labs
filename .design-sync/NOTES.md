## Repo shape
- This is an **application**, not a published component library. `dist/` is the bundled
  Cloudflare/Vercel app, not a component barrel; there is **no shipped `.d.ts`**.
- Source shape: `package` (no Storybook). Stack: shadcn/ui "new-york" + Radix + Tailwind v4
  (`@tailwindcss/vite`) + `class-variance-authority` + `clsx`/`tailwind-merge`, React 19.

## How the bundle entry works (important)
- No dist barrel → we use a hand-authored barrel:
  `labs/ownmail/packages/app/design-sync-entry.tsx` (`cfg.entry`, repo-root-relative),
  `export *` from each scoped component file.
- The barrel MUST live **inside the app package dir** — the converter derives `PKG_DIR`
  by walking up from `cfg.entry` to the first named `package.json`. Under repo-root
  `.design-sync/` it would resolve PKG_DIR to the repo root and every package-relative
  path (`cssEntry`, `componentSrcMap`, `extraFonts`) would break.
- Barrel is gitignored + regenerated by `node .design-sync/gen-entry.mjs` from
  `cfg.componentSrcMap` (run it before `package-build` on a fresh clone / re-sync). Source
  of truth is `cfg.componentSrcMap`; the generator keeps the barrel in sync automatically.
- Components' `#shared/...` subpath imports resolve via the app package.json `imports` map
  (esbuild handles this natively — no tsconfig `paths` exist).
- Build: `node .ds-sync/package-build.mjs --config .design-sync/config.json
  --node-modules labs/ownmail/packages/app/node_modules --out ./ds-bundle`
  (`--node-modules` → the app package's own node_modules, where react/radix resolve).

## CSS / tokens / fonts
- `cfg.cssEntry` → the **compiled** Tailwind output `dist/client/assets/styles-<hash>.css`
  (~65 KB, all tokens + used utilities). Raw `src/styles.css` is NOT usable (it's
  `@import "tailwindcss"` source needing the compiler).
- ⚠️ **Hashed filename is fragile** — changes on every app build. Regenerate with
  `pnpm --filter @ownmail/app build:cloudflare`, then update `cfg.cssEntry` to the new hash.
- Fonts: Manrope + Poppins via `cfg.extraFonts` (bare woff2 from `public/fonts/`); the
  compiled CSS's `@font-face` rules are harvested and rewritten to `fonts/`. Verified
  Poppins 400/500 load. The "add a matching @font-face" warn on extraFonts is benign.

## .d.ts contracts
- Synth mode can't resolve `React.ComponentProps<..> & VariantProps<..>`, so each
  component's props are **hand-written in `cfg.dtsPropsFor`** (variant/size unions, etc.).
  Keep these in sync with the real component signatures when the source changes.
- The `[DTS_PARSE]` check needs the CLASSIC typescript API. The repo pins TS 7 (native),
  whose npm package doesn't expose `import('typescript')`. We installed `typescript@5`
  into `.ds-sync/node_modules` for the check. On a fresh clone re-run
  `(cd .ds-sync && npm i typescript@5)` or the parse check silently skips.

## Verification method
- Chromium is NOT installed; `package-validate.mjs`'s render check is skipped with
  `--no-render-check` (user-approved). Previews were verified visually via the **Playwright
  MCP browser** (serve `ds-bundle/` with `.ds-sync/storybook/http-serve.mjs`, navigate +
  screenshot). To run the mechanical `[RENDER]` gate on a future sync, install chromium.
- Overlay components use `cfg.overrides.<Name>.cardMode: "single"` + a `viewport`
  (Dialog, Tooltip). Select shows a closed trigger; open dropdown is interaction-only.
  ScrollArea's overlay scrollbar/fade are hover-gated (not visible in a static shot).

## Known render warns (triaged as legitimate)
- `[RENDER_SKIPPED]` — expected; render check intentionally not run (MCP-browser mode).

## Re-sync risks (watch-list)
- `cfg.cssEntry` hash goes stale after any app rebuild (see CSS section).
- Barrel is gitignored — regenerate with `node .design-sync/gen-entry.mjs` before building.
- `dist/` is gitignored — a fresh clone has no compiled CSS until the app is built
  (`pnpm --filter @ownmail/app build:cloudflare`).
- `typescript@5` in `.ds-sync` is needed for the `.d.ts` parse check (repo ships TS 7).
- Grades live in gitignored `.design-sync/.cache/review/` (MCP-verified, all `good`).
- `.design-sync/conventions.md` names concrete token/utility/component vocabulary — if the
  Tailwind theme or component APIs change, re-validate those names against the fresh build.
